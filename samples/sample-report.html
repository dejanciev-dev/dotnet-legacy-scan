What makes this migration hard

  • ASP.NET Web Forms pages ×3 in LegacyShop.Web

    Web Forms does not exist on modern .NET. Rewrite the UI (Blazor or Razor Pages). Migrate incrementally: put an ASP.NET Core app with YARP in front, move pages one by one, and share session/auth with System.Web adapters.

  • ASP.NET Membership / Forms Authentication / Roles ×3 in LegacyShop.Web

    Move to ASP.NET Core Identity (or an external IdP). Plan the user/password-hash data migration and keep a compatible password hasher so users do not need to reset passwords.

  • WCF service hosting (.svc / system.serviceModel services) ×2 in LegacyShop.Services

    Server-side WCF is not part of modern .NET. Options: CoreWCF (closest, keeps contracts and clients), or redesign to gRPC / REST. Choose per client: who consumes this service and can they change?

  • Crystal Reports / ReportViewer ×1 in LegacyShop.Reports

    No direct support on modern .NET web. Options: keep a small .NET Framework reporting service, move to SSRS/Power BI embedding, or a .NET reporting library.

  • ASMX web services ×1 in LegacyShop.Services

    Not supported on modern .NET. Re-implement as Web API endpoints or host with CoreWCF (basicHttpBinding) to keep the SOAP contract for existing clients.

  • Web Forms user controls / master pages ×2 in LegacyShop.Web

    Rewrite as Blazor components / Razor layouts and partials.

Recommended migration order

Dependencies first. Shared libraries are multi-targeted so the old and the new application can run side by side during the migration.

  1. LegacyShop.Core Class library
    Remove System.Web dependencies, then multi-target net48;net10.0 (or netstandard2.0).
  2. LegacyShop.Modern Class library
    Already on modern .NET
  3. LegacyShop.Admin ASP.NET MVC
    ASP.NET Core MVC on net10.0. Large apps: incremental migration with YARP + System.Web adapters.
  4. LegacyShop.Reports Class library
    Multi-target net48;net10.0 (or netstandard2.0) once its major and blocker findings are resolved.
  5. LegacyShop.Services WCF service
    CoreWCF on net10.0 (keeps contracts/clients) or redesign as gRPC / REST.
  6. LegacyShop.Web ASP.NET Web Forms
    New ASP.NET Core app (Blazor or Razor Pages). Migrate page by page behind YARP, share auth/session via System.Web adapters.
  7. LegacyShop.Tests Tests
    net10.0, same test framework with updated packages. Migrate together with the project under test.

How this estimate is made

dotnet-legacy-scan reads project files, configuration, NuGet packages and source code (comments and strings excluded) and matches them against 37 migration rules. Each rule carries a heuristic effort; solution-wide concerns such as moving users to ASP.NET Core Identity or replacing the reporting platform are charged once, not per project. Totals add 3h per project and 30% for regression testing; the range is ×0.75 to ×1.6. It is a starting point for planning, not a quote. UI redesign, new features, infrastructure and deployment changes are not included.

The scan runs locally and read-only. No code leaves the machine.
